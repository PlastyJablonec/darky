# Profile dates

Apply `profile-dates-migration.sql` to the Supabase database before deploying the profile settings feature. Each signed-in user can optionally enter a birth date and name day in Settings; clearing a field removes that date. Dates are stored separately from public profiles and are readable by the owner and authenticated users with a recorded wishlist share from that owner. The shared-list overview displays the next anniversary without exposing the birth year in the interface. The recipient can access the stored date through the database API. A February 29 anniversary is observed on February 28 in non-leap years.
`nName-day suggestions use the MIT-licensed namedays-cs Czech calendar. A single matching date is suggested in settings without saving it; multiple dates are offered for selection. Google birthday import uses the People API and a separate, user-initiated OAuth consent request. The provider token is used for a one-time read and the returned date is placed in the form for review before saving. The app validates the returning account and never overwrites the stored value automatically. The Google Cloud project must enable People API and configure or verify the birthday-read scope as required by Google. Standard sign-in does not request that scope.
